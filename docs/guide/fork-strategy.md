# Fork 策略

## 版本锁定

| 项目 | 值 |
|------|------|
| Fork 基准 | Element Plus **2.14.2** |
| Fork 日期 | 2026-08-27 |
| 锁定方式 | `package.json` 中使用精确版本（无 `^` 前缀） |

## 为什么锁版本

使用 `^2.9.7` 这样的语义化版本范围，实际安装可能跳到 `2.14.x`，中间的 breaking changes 可能导致：
- CSS 类名变更导致样式丢失
- 组件 API 变更导致运行时报错
- 内部实现变更影响我们覆盖的层级

**所有项目必须使用精确版本**：`"element-plus": "2.14.2"`（无 `^` 或 `~`）。

## 上游更新评估流程

当 Element Plus 发布新版本时：

1. **创建评估分支**：`ep-evaluate/2.x.x`
2. **运行 diff**：对比我们修改过的文件与上游变更
3. **评估决策**：
   - 无冲突 → 合并，升级版本号
   - 有冲突 → 人工评估：
     - 上游修的是 bugfix → 合并
     - 上游加了新功能 → 评估是否需要
     - 上游改了我们覆盖的层级 → 以我们为准，跳过
4. **测试验证**：全量回归测试
5. **合并到主分支**

## 禁止事项

- 禁止使用 `npm update element-plus` 自动升级
- 禁止在 CI 中自动更新 EP 版本
- 禁止在未评估的情况下合并上游变更
